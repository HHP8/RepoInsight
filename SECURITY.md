# Security policy

Security fixes are supported for the current 1.0 release line.

Do not open a public issue for a suspected vulnerability. Use the repository host's private security-advisory channel and include the affected version, impact, minimal reproduction, and suggested mitigation. Remove credentials and private repository data. If no private channel is configured, contact a maintainer privately and ask for a secure reporting destination before sending details.

Maintainers will acknowledge a complete report when available, validate it against the documented threat model, coordinate a fix and disclosure, and credit the reporter if requested. Out-of-scope host-compromise and privileged-race cases may be documented rather than treated as product vulnerabilities.
